# Установка Nute Notes на собственный сервер

Инструкция создаёт **пустой независимый экземпляр с одним новым владельцем**. Для другого человека нужен отдельный экземпляр с новой базой и ключами. Публичной регистрации и добавления второго владельца нет.

## Подготовка

Нужен новый VPS с Ubuntu 24.04/26.04, systemd и root-доступом. Рекомендуется от 2 ГБ RAM и запас места под копии. Публикация исходников 0.5.0 не означает проверки всех конфигураций ОС.

1. Сохраните SSH-доступ и снимок чистого VPS.
2. Настройте A-запись домена, например `notes.example.org`, на VPS. Если есть AAAA, IPv6 тоже должен вести на него. Для выпуска сертификата используйте прямой DNS; CAA, если задана, должна разрешать Let's Encrypt.
3. Разрешите TCP 80/443 в firewall провайдера и ОС, сохранив SSH-порт. Порт 80 нужен и для продления сертификата. Установщик не меняет firewall, SSH или DNS.
4. Получите и просмотрите исходники: скрипт запускается от root, поэтому используйте доверенную ревизию.

```bash
sudo apt update
sudo apt install git
git clone https://github.com/mrnuked/nute-notes.git
cd nute-notes
git rev-parse HEAD
```

Сохраните ревизию для диагностики. Вместо клонирования можно скачать серверный архив и контрольные суммы из [выпуска 0.5.0](https://github.com/mrnuked/nute-notes/releases/tag/v0.5.0), проверить файл и распаковать его в отдельный каталог; файлы в архиве находятся сразу в корне. Собственный серверный архив создаётся командой `npm run package:server`.

## Запуск

Команды выполняются на **новом VPS**. Подставьте свой домен в нижнем регистре, международный — в punycode; email используется для сертификата.

```bash
sudo bash installer/install.sh --domain notes.example.org --email admin@example.org --check
sudo bash installer/install.sh --domain notes.example.org --email admin@example.org
```

`--check` проверяет ОС, конфликты системных путей, портов, базы, состав исходников и разрешение DNS. Он не доказывает внешнюю доступность всех A/AAAA и выпуск сертификата. Основной запуск загружает пакеты ОС и запрашивает Let's Encrypt, принимая условия сервиса.

Установщик отказывается перезаписывать существующие пути Nute Notes, базу/пользователя `nute`, сертификат домена и конфликтующие сайты. Это **новая установка**, не обновление. Не удаляйте найденные данные ради обхода отказа.

## Что создаётся

- Nginx с корнем **только `/srv/nute/current/public`**, HTTPS и перенаправлением HTTP, кроме ACME challenge.
- Код в `/srv/nute/releases/initial`, ссылка `current`, отдельный пользователь `nute`.
- Отдельный PHP-FPM-пул и `/run/php/nute.sock`, закрытые сессии `/var/lib/nute/sessions`.
- Новые MySQL-база и пользователь `nute` со случайным паролем. После инициализации остаются права чтения и записи без создания таблиц.
- `/srv/nute/private/config.php` с новым ключом приложения и настройками, режим 0640, доступ root и группе `nute`. Токен владельца — `first-owner.txt`, режим 0600.
- Продление TLS через `certbot.timer`, перезагрузка Nginx после продления.
- Ежедневные закрытые локальные копии через `nute-backup.timer`; первая создаётся до регистрации владельца.

Другие сайты и общие PHP-пулы не удаляются, глобальная конфигурация MySQL не заменяется. Срок сессий согласован с пределом приложения 180 дней.

## Первый владелец

```bash
sudo cat /srv/nute/private/first-owner.txt
```

Откройте `https://notes.example.org/?setup`. Введите токен, email владельца, уникальный мастер-пароль не короче 16 символов. Настройте TOTP и подтвердите код. Сохраните десять резервных кодов отдельно от сервера и телефона.

После регистрации токен перестаёт действовать, повторная регистрация запрещена. Email владельца и email сертификата могут различаться.

**Восстановления забытого мастер-пароля нет.** Резервные коды заменяют TOTP, но не пароль. Подробнее — в [руководстве](USER-GUIDE.md).

## Проверка

```bash
sudo nginx -t
sudo systemctl status nginx mysql nute-backup.timer certbot.timer --no-pager
curl -fsS 'https://notes.example.org/api.php?action=bootstrap'
sudo certbot renew --dry-run
sudo /usr/local/sbin/nute-backup
sudo ls -lh /var/backups/nute
```

После регистрации bootstrap должен содержать `"initialized":true`. Из внешней сети проверьте вход, создание тестовой заметки, повторный вход, синхронизацию двух устройств, удаление и экспорт.

Проверьте, что `/private/config.php`, `/server/Core.php`, `/database/mysql.sql` недоступны по HTTP. Получение `/assets/app.js` нормально: браузеру нужен клиентский код. Серверные секреты в него не входят.

## Если TLS не завершился

Если установка дошла до ожидания TLS, база, конфигурация и токен уже существуют. Исправьте DNS, порты или CAA, затем с прежними параметрами:

```bash
sudo bash installer/install.sh --domain notes.example.org --email admin@example.org --finish-tls
```

Режим разрешён только при сохранённом `tls-pending.sha256` и неизменённых конфигурации и собственных Nginx/PHP-файлах. Он не создаёт БД заново. После успешной установки повторный запуск запрещён.

Если сбой произошёл раньше появления этого состояния, автоматического продолжения нет. Изучите ошибку и `journalctl`. На ещё пустом VPS можно восстановить первоначальный снимок. При наличии владельца или заметок сначала сохраните БД, исходный `config.php` и пользовательский экспорт. Не запускайте `init.php` поверх существующего аккаунта.

## Копии и обслуживание

Архивы `/var/backups/nute/nute-*.tar.gz` содержат БД, исходный `config.php` и сведения о выпуске. Архив целиком **не зашифрован дополнительно**: записи в БД зашифрованы, но конфигурация содержит секреты. Храните защищённые копии вне VPS.

Старые локальные копии автоматически не удаляются. Контролируйте место, проверяйте внешние копии и задайте свой срок хранения.

```bash
sudo systemctl list-timers nute-backup.timer certbot.timer
sudo journalctl -u nute-backup.service -n 50 --no-pager
df -h
```

Для полного восстановления нужны БД **и тот же `config.php`**, а для чтения заметок — мастер-пароль. Новый ключ из повторной инициализации старый не заменяет. Проверяйте восстановление на изолированном стенде. Эта инструкция не включает автоматическое восстановление или обновление существующего сервера.

Обновляйте ОС, отслеживайте сертификат и новые версии проекта. Обновление приложения требует плана выпуска, резервной копии и проверки схемы; fresh-install для этого не подходит.

## Клиенты

Веб работает по адресу вашей установки. [Настольные клиенты](DESKTOP.md) предлагают домен при запуске; [Android](ANDROID.md) собирается под нужный origin.

Новый домен не переносит аккаунт, cookie, доверие и очередь автоматически. Перед сменой клиента или домена синхронизируйте правки и сохраните экспорт. Не переносите профиль одного сервера поверх другого.
